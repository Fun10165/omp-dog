# DoG 图的写法:从公理长出一株树

## 动机

门禁只提供批评那一半;生成这一半难在分解。非形式化的标准没有闭式定义,凭直觉列条目必然长成清单:清单既不全,也不稳,还会越改越膨胀。这一页是被验证过的一条路径——先用一句话定功能(公理),再用「失败方式」这一条规则递归,最后用划分法的老规矩验合法性。每一条都有判词作证(见文末实证)。

## 设计

### 1. 先写公理,再谈节点

把对象当成**实现某个功能的装置**,把功能写成一整句话。根节点是这句话本身。

- 公理里的每个词都是约束:「相信」逼出「依据」与「不被误导」;「只读这份材料」逼出「记录」;「读者」逼出「接收」;「那个判断」逼出「主张」。
- 判定公理是否合格:显式写出来;若换成另一条公理,树会立刻变成另一株(说明公理在起作用)。
- 第一性原理只管顶端。所有下层由失败方式递归得到,不要再回公理重推,否则会出现两套依据。

### 2. 失败方式递归(核心规则)

- **父节点是一句可被破坏的性质**,不是给一堆东西起的名字。「观察顶得住」是性质;「诚实与可复现」是标签。
- **子节点是父性质在下一层的失败方式**:把父固定为「成立」,问「它可以怎样失败」。每个失败方式就是一个子节点。
- 子节点自己还能被同样地问出多种失败方式,它就成为新的父,抽象层级降一级;直到判断单一,才是叶子。
- 三条蕴涵检验:子失败必然破坏父;子之间互不蕴含;拿掉任一子,父无法被完整刻画。

### 3. 四个问题,各有证明形式

- **为什么是这些**:由第 2 节的递归给出,每个子都能顺回公理。
- **只有这些(穷尽性)**:需要固定参照物,三种可用 —— 否定形式二分(偏移只有「多于真相」与「少于真相」)、生成过程穷尽(读者拿注意力只有三个去处:寻找、解码、被无内容处占用)、链条失败位置穷尽(按时重做只有取不到、信息缺、读数对不上三个位置)。
- **其他的为什么不是**:给每个候选一个归属判定(它失败时破坏哪条已有性质),或说明它属于场所约定与传输之后的结果(伦理审查、引用数量、格式模板)。
- **不能更少(最小性)**:给出分离案例 —— 两份实例,一个在此条失败而在彼条通过,反过来也成立。分离案例就是构造模型,写不出来说明切分未成立。

### 4. 领域知识怎么进场

领域条目**不许直接当节点**(那会长成清单;曾一次挂出 45 条,被元图判词逼回 28 条)。三种正确用法:

- **反例库**:每条性质需要真实的失败方式(数据污染是「其他解释没被排除」的实例,重复发表是「来源信息不少」的实例)。
- **穷尽性检验**:拿官方清单逐条问「它破坏哪条性质」;答不出的条目说明结构少一条性质。
- **分离案例来源**:用代表作品的差异做模型(GPT-3 不发布代码与权重:记录失败而依据成立;Transformer 无不确定性量化:观察的强度未定而推理站得住)。
- 只对部分对象成立的条目(数据污染、人类参照),做某条性质在条件下的失败方式,把条件写进目标文本。

### 5. 划分法:子项排列怎么定

形式逻辑的划分老规矩,正好对应元图的结构判据:

| 划分规则 | 对应判据 |
| --- | --- |
| 同一划分依据(每次只用一个差异切一刀) | 同层同一抽象面 |
| 穷尽(盖住被划分者) | 覆盖面 |
| 互斥(各支互不包含) | 叶子不可再拆、无重复 |
| 不越级(每级只降一层) | 父是子的抽象 |

排列是一株向下生长的树:从最高的种(公理)出发,每次选一个差异切一刀,切出的两支必须同层。切分依据可以选,一旦选定就决定了子项排列;中途换依据等于重新划分——最初的两次失败都出在这里:条目先摆好,再临时找依据。

### 6. 防止子项放错分支:四条检验

1. **主语检验**:子项失败时的主语与父项是否同一对象(把「读者一侧的症状」放在「主张」下、把「失真」叫成「传输过程」,都是主语错位)。
2. **蕴涵检验**:子失败是否必然破坏父;若毫无影响,它属于别处。
3. **修复检验**:修这条失败要动的是论证、观测、材料,还是文本;与父母所属层级对照(排除替代解释归「观察」,因为要补的是实验,不是证明)。
4. **反向占用检验**:把它拿掉,父是否残缺;移到候选父那里,是否与别的子项重叠。

经验一句:**看它失败时的对象与动作,不要看它用了什么工具。**

## 规格(照做清单与已知坑)

- 节点文本只写状态,不写动作:出现「逐条看」「即 fail」「并指出」这类就是写成了做法。
- 不出现黑话与生造词组;术语用领域内通用词。
- 规模纪律:先自下而上找性质,再决定叶子;出现二十条以上并列条目时,回头找它们的公共性质。
- **提交背景(`specific.md`)里必须有外部来源清单**(官方标准页 + 代表作品的条目级清单)与用户原话。不写清单时,「覆盖」这一条判据看不见缺失——实证:同一张图,背景里只有来源名称时判全覆盖,换成条目清单后才逐项对照。
- 背景与对象必须同步:改完图后重写背景,否则验证者会记下「背景说 37/24,对象是 41/28」这种不一致。
- 迭代纪律:每轮全量重判(对象是整份图,任何改动都让所有判据重跑),所以攒够一批再跑;只对连续出现的判词动手。
- 判据之间有张力:能给「覆盖」加分的节点,可能因「验证者取不到证据」被判失败(实证:一条要求验证者去查「发表之后才出现的检验」的叶子)。给叶子写目标时先问:它能不能只凭冻结对象判定。
- 叶子粒度:带并列举例的叶子容易被判「可拆」。写法是把同源并列项收在一个统摄语之下(如「影响可信度的来源信息」),或干脆拆成两片。

## 实证

- 成品:`examples/paper-excellence.graph.json`(41 节点 / 28 叶),五条一级来自公理句的槽位。
- 三轮元图验收(`do-dog-genesis`,每次 16 条判据、约 7 分钟)的结果:第一版 21/21 通过但内容薄(缺十余条判据);第二版 18 过 5 败(根因:四片叶子可拆、一条要求取证不到);第三版 18 过 3 败(根因:一片叶子可拆,含「局限/失败」与「更广泛影响」两类)。原始判词与证据是本地验证产物,不入库。
- 反向结论:元图能判自洽、抽象与措辞,判不了「相对一份没写下来的标准还缺什么」——那份标准必须先变成条目级清单,写进提交背景。
